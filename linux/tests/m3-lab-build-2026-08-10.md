# M3-lab build evidence — 2026-08-10

Status: **build-only; not flashed**.  This records the first profile that
contains the NOMMU BusyBox `inetd` front-end and a password-enabled Dropbear
for the private bring-up test.  It does not prove C6 SDIO, Wi-Fi, DHCP, or SSH
on hardware.

## Build inputs

- Profile: `build-m1.sh --profile m3-lab`
- Build container: `espressif/idf:v5.5.3` with Buildroot host utilities
  `file`, `cpio`, `rsync`, and `bc` installed for the run
- Source cache: external pinned checkout; `verify-source-lock.py` passed for
  five immutable sources
- Target: RV32 NOMMU, Linux 6.18.35, 16 MiB flash / 32 MiB PSRAM contract
- Wi-Fi credentials: **not supplied**, so `/etc/easystick/wpa_supplicant.conf`
  is intentionally absent from this image

## SSH image checks

The SquashFS image contains:

- `pi` UID/GID 1000 with the documented `raspberry` lab password hash;
- BusyBox `inetd` and `/etc/inetd.conf` for Dropbear TCP/22;
- Dropbear compiled with password and public-key authentication, with root
  login disabled by the inetd command line;
- `S40network` module load / WPA2 / DHCP sequence and `S85easystick-ssh`.

The host key is generated in `/tmp` at boot and is intentionally not
persistent.  Replace this profile with production M3 key-only provisioning
before a non-lab test.
