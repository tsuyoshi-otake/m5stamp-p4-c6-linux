# v0.6.0 hardware validation (2026-11-15)

Board: M5Stack Tab5 (ST7121 panel, A164 keyboard attached), P4 USB
Serial/JTAG on COM13.  Only the P4 flash was written; the C6 was not touched
(it already ran ESP-Hosted-NG 1.0.6).

v0.6.0 is the first release of the Tab5 port.  It is `main` at 7c63604: the
Tab5 bring-up (#1, #2), the SoftAP fix (#4), the Dropbear fix (#5), the
keyboard (#7, #13, #14), the simplefb mmap fix (#15), `boot-edit` (#20) and
the fixes shared with the Stamp-P4 port.  The release build sets
`NOMMU_POOL_BESTFIT=1`, `NOMMU_USER_RESERVE=1` and `NOMMU_SYSTEM_MARK=1`
through `linux/release-build.sh` (#8).

## Not covered

- Key presses and touches were not repeated on the CI image (the devices
  were detected; typing and touch were checked with branch builds in #2,
  #13 and #14).
- The 16 MB image was not flashed, so a blank-drive first boot (new
  credentials, Wi-Fi QR) was not repeated on this image (#9 covers it on a
  branch build).
- Before the flash, on the previous local build, the SoftAP did not come up
  after a cold power-on and after a `reboot`: the C6 timed out on SDIO
  (`tx_process: Failed to send data: -110`, `CMD53 read/write error`) while
  the boot still reported `SoftAP started`.  After an RTS or esptool hard
  reset it came up every time, also on this image.  This is tracked in #22;
  a cold power-on of this image was not tried.

## Blank-flash first boot (#39), 2026-11-16

The v0.6.0 release 16 MB image (`m5stack-tab5-linux-smp-v0.6.0-16mb.bin`,
SHA-256 `255f894d…7244`, verified against `SHA256SUMS.txt`, exactly
16777216 bytes) was written to a fully erased flash on COM13:
`esptool.py --chip esp32p4 erase_flash` then `write_flash 0x0 <image>`
with verify (`Hash of data verified`).  `flash-candidate.ps1` was not used
for this step because it preserves the boot drive.

| Check | Result |
|---|---|
| First boot from blank flash | PASS — `check-boot-log.py` 15/15 PASS; `ES_CREDENTIALS` generated new passwords, `ES_HOSTKEY` generated keys, SoftAP `m5-E2CA` (ch 11, 192.168.4.1) |
| Wi-Fi QR on the panel | PASS — photographed with the PC webcam, decoded with pyzbar; the QR SSID matches the SoftAP SSID `m5-E2CA`. The new credentials were saved on the test PC (not printed, not committed) |
| Second boot (`reboot`) | PASS — no `ES_CREDENTIALS NEW`; passwords applied from the boot drive; `ES_HOSTKEY NONEMPTY_OK`; same SSID `m5-E2CA`; 15/15 PASS; no QR on the panel (camera + decoder) |
| Touch corners (old DT transform) | PASS as documented defect — taps reported (57,650) TL, (55,48) TR, (1190,60) BR, (1217,640) BL = swap_xy + mirrored y, the pre-#33 transform; no driver errors |
| Two-finger press | Not concluded — no second contact was recorded in this run; multi-touch was not re-tested on `main` |
| A164 keyboard (I2C `0x6d`, `tab5-kbd`, event1) | PASS — attach logged `attached, fw 0x01, polling at 40 Hz`; typed keys decoded as EV_KEY/EV_MSC/EV_SYN groups (a,b,c; `Aa`+d → shift+D; `sym` tap → sticky LEFTSHIFT modifier wrapping the next key → shift+1); detach/reattach logged `MCU restarted … detached … attached` |
| `poweroff` | Recorded defect — halts only (no PI4IOE5V6408/PWROFF driver in v0.6.0; #31 landed later); panel stays lit, then the HP watchdog (`rst:0x7 HP_SYS_HP_WDT_RESET`) reboots the board |
| 3 chip resets (DTR/EN via COM13) | PASS — each boot 16/16 PASS on `check-boot-log.py`, kernel `#1 SMP Sat Nov 14 22:20:12 UTC 2026`, credentials applied (never regenerated), SoftAP up |
| Post-boot C6 collapse (cycle 3) | Recorded — after one clean boot the SDIO link later threw `CMD53 read/write error` + command timeouts → `esp_stop`; a following single chip reset recovered it (0 errors, wlan0 UP). Rapid back-to-back EN resets can wedge the C6 mid-init; relates to #22 |

Restore to `main` (`f4a8921` tree = the B7 release build, README-only diff
so the image was reused): `flash-candidate.ps1 -Port COM13
-AllowCandidateWrite -Board tab5 -PythonPath py` — no `-WriteBoot`, boot
slots + boot drive preserved; all six writes `verify OK`.  Boot on the
restored image: 16/16 PASS, `uname -v` = `#1 SMP Mon Nov 16 04:10:30 UTC
2026`, SoftAP `m5-E2CA` up, wlan0 UP/LOWER_UP.  Credential persistence:
the boot drive's `credentials.txt` hashed the same before and after the image swap; `/etc/shadow` and the dropbear host key differ per boot *by
design* (S85ssh regenerates them every boot).  Touch on `main`: event0 =
`st7123-touch`; the live DTB touch node has no `touchscreen-swapped-x-y` /
`touchscreen-inverted-x` — raw axes per the #33 spec.
