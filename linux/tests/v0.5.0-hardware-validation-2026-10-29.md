# v0.5.0 hardware validation (2026-10-29)

Board: M5Stamp ESP32-P4 + C6 (SDIO), P4 USB Serial/JTAG on COM10.  Only the
P4 flash was written; the C6 was not touched.

v0.5.0 is v0.4.3 with Deep Sleep (#56), the temperature wake through the LP
core (#57), the earlycon fix (#58), the user LP core program (#59), and the
#55 one-release compat aliases removed.  The release build sets
`NOMMU_POOL_BESTFIT=1`, `NOMMU_USER_RESERVE=1` and `NOMMU_SYSTEM_MARK=1`, as
v0.4.3 did.

On the board, `/etc/build-info` reads `version=v0.4.3-14-gbce0f60`,
`git=bce0f60e37eb`, `dirty=0` and `build_date=2026-10-28T23:42:39Z`.

Before the flash the board was running the Deep Sleep cycle example from its
drive (`main.py`, 60 s asleep).  The flash was retried until the board was
awake (third try).  After the reset the autorun program was stopped from the
serial console and `main.py` was deleted from the drive (loop-mounted
`boot.img`; bootsync saved it to flash), so the checks below ran without
sleeps.

|---|---|

| Boot | `/sys/devices/system/cpu/online` `0-1`; init scripts `S00mounts S05tmpfs S40network S45bootsync S85ssh S90watchdog`; the board came back on the lab WLAN with its saved settings; SSH key auth to `stamp-p4.local` works |
| Compat aliases removed (#55) | none of the old command links in `/usr/sbin`, no old status file in `/run`, no old directory in `/sys/kernel/`; the old `.local` name no longer resolves from the PC (the names are listed in `issue55-rename-2026-10-23.md`) |
| New names | `/usr/sbin` has `sysinfo autorun update-status run-system bootsyncd respawn mdnsd watchdog-feed usb-lun boot-commit firstboot sdio-diag deepsleep`; `/run/status.txt` present |
| Deep Sleep / LP core sysfs | `/sys/kernel/board/` has `deep_sleep sleep_memory wake_info wake_reason lp_core`; `wake_reason` `reset`; `lp_core/state` `state=stopped mode=none ram_base=0x50108100 ram_bytes=16384` (no program configured) |
| Deep Sleep on this image (serial console) | `echo v050 > sleep_memory; deepsleep 10`: `boot: DEEP_SLEEP timer_ms=10000`, then `boot: WAKE boot=2 causes=0x1 slept_ms=11236`, `ES_WAKE: reason=timer`; after the wake `wake_reason` `timer`, `sleep_memory` `v050`, and `date` was 01:11:59 UTC against 01:12:00 on the PC |
| #54 crash scenario (`nommu-mem-harness.py --scenario crash --transport lan`, default N: 4 held sessions, 5 `S40network restart`, then 20 sequential SSH probes) | recovery 82.9 / 22.3 / 22.3 / 22.3 / 22.3 s; 20/20 reached auth, 20/20 returned the marker, 0 post-auth closes, 0 `Unable to access instruction` |
| Pool after that run (1452 s up) | used 6160384 of 10485760, `alloc_fail` 0, `system_alloc_fail` 0, `fallback` 25, `user_denied` 25, `largest_free` 3719168; dmesg has 11 `nommu: Allocation ... failed` and 7 `page allocation failure` lines and no `Oops` (the case-insensitive `oops` matches are the `ramoops` boot lines) |

The first recovery (82.9 s) was longer than in v0.4.3 (32.1 s); the four
after it were 22.3 s each.  All 20 probes still passed.

Deep Sleep, the temperature wake and the LP core program were checked on
hardware with the branch builds before the merge (issues #56, #57 and #59,
including the PPK2 current measurement in #56); on the release image only
one timer sleep was repeated (above), after the crash scenario.
