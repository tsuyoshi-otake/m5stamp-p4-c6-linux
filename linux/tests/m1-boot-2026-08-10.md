# M1 boot evidence — 2026-08-10

Status: kernel and root filesystem reached `/sbin/init` on the assembled
Stamp-P4 module.  This is a bring-up result, not an M1 release or an SSH
acceptance result.

## Test setup

- Board: EasyStick Stamp-P4 Rev0.15 hand-assembled target, ESP32-P4 rev1.3
- Flash: 16 MiB DIO; PSRAM: 32 MiB
- Capture port: module USB-C `COM10` (USB Serial/JTAG)
- Reset/flash tool: esptool 4.8.1, Python 3.12.10
- The rootfs was written at `0x710000`; esptool reported `Hash of data
  verified` and performed a hard reset.

Raw capture is intentionally kept outside the repository to avoid treating
serial logs as firmware inputs:

```
C:\Users\developer\tmp\easystick-p4-boot-20260810-abi-fixed.log
SHA256 1f0812ccac418b383d1cdccdf3efc3316b2fcd2ab2d27b68f814712007be76af
Bytes  8220
```

The checked-in PowerShell collector was also smoke-tested against `COM10`
with reset enabled; it wrote a 3928-byte raw file and sidecar manifest using
the same host-side SHA-256 procedure.

## Observations

- The ESP-IDF boot shim validated the M1 artifact bounds and jumped to
  `0x48000000`.
- Linux 6.18.35 started with RV32 `acim` capabilities (no F/D extension).
- CLIC, SYSTIMER, cache, UART, and the USB-JTAG early console initialized.
- SquashFS mounted read-only and Linux invoked `/sbin/init`.
- The prior `SIGILL` caused by an F-extension `fsw` instruction was not
  present in this capture.  The Buildroot toolchain is now checked for
  `rv32imac*` and `ilp32` before images are accepted.

## Limits and next gate

The kernel command line selects `console=ttyS0,115200`.  `ttyS0` is the P4
UART0 at `0x500ca000` on GPIO38/GPIO37; `COM10` is USB Serial/JTAG and only
provided the early boot console in this test.  Therefore this log proves
boot-to-init, but does **not** prove an interactive login, Wi-Fi, or SSH.
Attach the documented UART fixture (or add a reviewed USB-JTAG tty driver)
before attempting the `pi` first-boot account.  M2 C6 SDIO and M3 SSH remain
pending and must not be inferred from this result.

Cold-boot repetition and recovery-cycle acceptance are also pending; retain
the stock flash readback and use `tests/capture-boot.ps1` for subsequent raw
captures and sidecar hashes.
