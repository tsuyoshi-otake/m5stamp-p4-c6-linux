# v0.4.3 hardware validation (2026-10-24)

Board: M5Stamp ESP32-P4 + C6 (SDIO), P4 USB Serial/JTAG on COM10.  Only the
P4 flash was written; the C6 was not touched.

v0.4.3 is v0.4.2 with the #55 rename (role names instead of the old project
prefix, with one-release compat aliases), udhcpc on its own minimal BusyBox
(#45) and `0092` (physmap maps `mtd-rom` at its exact size).  The release
build sets `NOMMU_POOL_BESTFIT=1`, `NOMMU_USER_RESERVE=1` and
`NOMMU_SYSTEM_MARK=1`, as v0.4.2 did.

## Not covered

- The 30-minute soak, the USB update and a `config.txt` apply were not
  repeated on the CI image; the code paths did not change in function since
  v0.4.2, only in name.
- The crash scenario ran with the harness default of 4 held sessions
  (v0.4.2's record used 6).
- AP mode was not checked.
- The 16 MB image was not flashed, so its blank-drive first boot was not
  repeated.
- An upgrade from a drive whose `config.txt` sets the old hostname was
  not tried on hardware.
