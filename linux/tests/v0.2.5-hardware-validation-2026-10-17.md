## An earlier build was not released

The first build for v0.2.5 (run 39025735550, commit 8231b4e) was flashed
the same way.  After the STA settings were written to the drive, the
network reload ran under bootsyncd's `umask 077`, `udhcpc` wrote
`/etc/resolv.conf` as `0600`, and `m5` could not resolve names: the autorun
`main.py` failed with `OSError: [addrinfo error -2]`.  v0.2.4 has the same
fault.  2f12c7d starts the reload and the autorun program with `umask 022`;
this record is for the rebuilt image.

## Results

The STA settings and the m5 password were written into the live drive
image from the serial console, as in the v0.2.4 record.  The autorun test
program is the `main.py` + `lib/helper.py` pair from
`autorun-micropython-validation-2026-10-17.md` (DNS, an HTTP `HEAD`, `json`,
`time.sleep`).

| Check | Result |
|---|---|
| `check-boot-log.py` after the flash | 11/11; `ES_AUTORUN STAGED` |
| First boot (blank A/B metadata) | `boot selection: legacy fallback slot0`; generated credentials saved to flash |
| config.txt (STA) and credentials.txt written into the live drive | bootsync: `Saved to flash`, password applied, `reloading network`; no reboot |
| `/etc/resolv.conf` after that reload | `-rw-r--r--`; `nslookup` and MicroPython `getaddrinfo` work as `m5` |
| `main.py` + `lib/` saved to the drive | started as `m5` (`SN python3 main.py`, umask 0022); `http b'HTTP/1.1 200 OK'`, a JSON line every 5 s |
| Edit `main.py` (v1 → v2) | restarted by itself (`main.py v2 start`) |
| `autorun restart` as `m5` | `stopped pid 651`, `started main.py pid 657` |
| `autorun=off` in `config.txt` | `--- autorun: stopped`, `mode=off`; `wlan0` `carrier_changes` stayed 0 |
| `timeout 2 sleep 8` | `Terminated`, exit 143 |
| `free`, `awk`, `xxd`, motd Autorun lines | OK |
| 3 resets with `main.py` on the drive | 11/11 each; `boot selection: generation=6 slot=0 crc=ee72eb3e` each; `autorun: started main.py` and HTTP 200 in the log each time; SSH login OK |
| Remove `main.py` and `lib/` | `not running`; `config.txt` md5 back to its value before the test; `boot_commit` `slot=1 generation=7` |

## Not covered

  emulated by a loop mount of `/tmp/boot.img` on the board.
- Power loss during a kernel flash write.
- A soak of hours on this image, and a client joining the SoftAP.
