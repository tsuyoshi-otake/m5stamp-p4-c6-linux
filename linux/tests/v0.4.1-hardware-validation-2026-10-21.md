# v0.4.1 hardware validation (2026-10-21)

Board: M5Stamp ESP32-P4 + C6 (SDIO), P4 USB Serial/JTAG on COM10.  Only the
P4 flash was written; the C6 was not touched.

v0.4.1 is v0.4.0 with the #35 fix and the #40 script changes.  #35: the
P4 SDMMC FIFO does not advance on CPU reads (`dw_mmc.fiford_mode=5` shows
`STATUS.FCNT` unchanged across each read), so a programmed-I/O read of more
than one word returned its first word repeated; `0087` and
`easystick,fifo-no-pop` route such reads through IDMAC with a bounce
buffer.  `0041`–`0043`, `0085` and `0086` are opt-in probes, off by
default.  #40: `S40network`, `easystick-update-status` and the udhcpc
script start fewer programs during a network restart.  The local checks
(images i4035a–h) are summarized in issue #35.

## Not covered

  repeated; the factory drive and boot-shim first-boot code did not change
  since v0.4.0, where that boot was checked.
- PIO writes: a transmit tail that rounds to 8 or 12 bytes still goes out by
  programmed I/O.  No corruption was seen, but no test isolates it.
- `mpytest.py`, `cmdcheck.py`, `shtest.sh`, the #43 UDP probes and the #44
  fault timing were not repeated; that code did not change since v0.4.0.
